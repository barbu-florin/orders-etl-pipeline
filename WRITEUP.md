During the cleaning step I explored orders_raw and identified several data inconsistencies that needed to be solved before loading the data into orders_clean.

Negative quantities: Some qty values were negative. After inspecting these records, I determined that they represented normal quantities with an incorrect negative sign. I therefore converted them to their absolute values.
Missing customer IDs: Some records had a missing customer_id. I found that the customer ID could be recovered from the customer_email, as the email contained the customer's ID. I extracted the ID from the email address and used it to fill the missing values.
Missing categories: Some records had a missing category. Since the same SKU appeared in other records with a valid category, I used the sku to identify the corresponding category and fill the missing values.
Inconsistent timestamps: The order_ts column contained multiple timestamp formats, including Unix timestamps, ISO timestamps, and European-style dates. I normalized all of them to a common datetime representation. Unix timestamps were interpreted as seconds, ISO timestamps were parsed directly, and slash-separated dates were interpreted using the DD/MM/YYYY convention.
SKU inconsistencies: I identified several SKU formatting issues. Some SKUs contained the letter O instead of the number 0, while others contained spaces instead of the - delimiter or were concatenated into a single string. I standardized these values to the expected SKU format.
Invalid unit prices: Some records contained 0 or 999999 as the unit_price. These values appeared to be invalid based on the other records. I checked whether valid prices existed for the same sku, fx_reference_date, and currency. When matching valid records existed, I replaced the invalid price with the average of those valid prices.
